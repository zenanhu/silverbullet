End-to-end request flow in SilverBullet. The browser sends HTTP requests (or the service worker proxies them from offline cache). The Axum router checks authentication (JWT cookie or bearer token) via auth middleware. Protected routes dispatch to specific handlers: /.fs/* for file CRUD (reads/writes to disk via DiskSpacePrimitives), /.runtime/* for Lua evaluation (proxied to headless Chrome via CDP, which runs the client in headless mode and calls sbRuntime APIs), /.shell for command execution, and /.proxy for reverse proxying. Open routes (/.ping, /.auth, /.logout, /) require no authentication.
